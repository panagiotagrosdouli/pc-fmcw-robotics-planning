## GitHub-hosted bundle generation

Workflow:

`.github/workflows/submission_bundles.yml`

The workflow:

1. regenerates publication figures/tables from archived evidence;
2. compiles all three canonical LaTeX manuscripts;
3. runs the deterministic repository submission-package builder;
4. renames the resulting archives by intended venue;
5. writes a publication snapshot manifest;
6. computes SHA-256 checksums;
7. uploads everything to GitHub Actions as artifact:

`submission-bundles-2026-09-28`

## Why the ZIP files are generated by Actions instead of committed directly

The repository connector used for manuscript maintenance writes UTF-8 text files through GitHub's Contents API and does not provide direct binary-file upload. Keeping the ZIP generation in GitHub Actions has two advantages:

- every bundle is rebuilt from the exact checked-out commit rather than manually copied;
- the checksums and compiled PDFs are tied to the same GitHub execution record.

The manuscript source, bibliography, claims audits, cover letters, readiness checklists, generated assets, and frozen evidence remain version-controlled in the repository.

## Rebuild

The workflow also supports manual `workflow_dispatch` from the GitHub Actions interface.

Do not edit generated ZIP contents by hand. Change the canonical manuscript/evidence files and rebuild instead.
