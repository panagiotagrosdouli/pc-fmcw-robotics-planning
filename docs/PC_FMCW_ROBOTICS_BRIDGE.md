# PC-FMCW → Robotics Planning Bridge

## Purpose

This document defines the simulation-only bridge between the Phase-Coded FMCW (PC-FMCW) ISCAI study in `PanagiotaGr/ISCAI_pc_fmcw` and the Stage-9 autonomous-motion-planning stack in this repository.

The goal is to evaluate predictive connectivity-aware motion planning without requiring an external autonomous-driving dataset. The study is therefore a controlled, reproducible, physics/model-based closed-loop simulation study. It must not be described as real-world validation.

## Upstream PC-FMCW chain

The upstream project studies the following processing chain:

PC-FMCW generation → DPSK phase coding → optical transmission → coherent reception → group-delay filtering → range-Doppler processing → target detection → Multidimensional Hough Transform trajectory estimation → adaptive illumination.

The robotics extension starts after target-state / trajectory estimation. It does not replace the upstream sensing and communication study.

## Stage-9 interface

At planning time k, the bridge exposes:

- ego state x_e(k) = [x, y, yaw, v]
- estimated target state / recent target history
- predicted target trajectory over the planning horizon
- candidate ego trajectories generated by the motion planner
- a frozen PC-FMCW-derived or explicitly declared surrogate link-quality model evaluated along each candidate trajectory

For candidate trajectory tau_i, future relative geometry is

r_i(k+j) = p_target_hat(k+j) - p_ego_i(k+j).

The connectivity predictor maps the trajectory-conditioned relative geometry to link metrics such as predicted SNR, BER, outage probability, or a normalized connectivity score. The exact metric may only be called PC-FMCW-derived when its equations/parameters are explicitly traced to the upstream PC-FMCW model.

## Planner variants

- P0: mobility-only baseline; no connectivity term.
- P1: reactive connectivity-aware baseline; uses present link state without trajectory-conditioned future prediction.
- P2: predictive connectivity-aware planner; scores future connectivity along each candidate ego trajectory.
- P3: risk-aware predictive planner; propagates target/prediction uncertainty through the same link-predictor interface used by P2.
- P4: oracle simulation baseline; uses future simulated target truth and is not deployable.

## Closed-loop protocol

1. Generate a deterministic scenario from a documented seed and parameter set.
2. Simulate target ground-truth motion.
3. Produce the target information available to the planner from the declared sensing/tracking model.
4. Predict future target motion without exposing future truth to P0–P3.
5. Generate ego candidate trajectories and hard-filter infeasible/colliding candidates.
6. Evaluate mobility and, where applicable, connectivity costs.
7. Select a candidate and execute only its first control action.
8. Advance the simulation and repeat until termination.

This is receding-horizon closed-loop simulation. P4 alone may access simulated future truth.

## Scenario family

The dataset-free benchmark should cover parameterized scenario families rather than a single hand-picked trajectory:

- lead vehicle with changing speed
- cut-in / lane-change target
- crossing target
- geometry-driven link degradation
- target maneuver with prediction-model mismatch
- combined safety/connectivity conflict

Each scenario family should be swept over multiple seeds and physically meaningful initial conditions. Results should be aggregated across scenarios/seeds, not reported from one illustrative run.

## Evaluation

Primary mobility/safety metrics:

- travel time / progress
- path length
- minimum inter-vehicle distance
- minimum TTC when defined
- collision / infeasibility rate

Primary connectivity metrics:

- outage fraction or outage duration
- predicted/realized SNR when supported by the frozen link model
- BER when supported by the frozen communication model
- connectivity survival probability / risk statistic for P3

Planning comparisons should report paired P0–P4 differences with confidence intervals and appropriate paired statistical tests across independent simulation seeds/scenarios.

## Scientific claim boundary

The simulation does **not** constitute a new optical measurement campaign, a real-vehicle trial, or real-world autonomous-driving validation.

Use the phrase **PC-FMCW connectivity** only when the link metric is generated by a frozen model whose equations and parameters are explicitly traceable to the upstream PC-FMCW system. Until that bridge is verified, use **connectivity surrogate/model**.

Synthetic perturbations are prediction/model errors, not sensor measurement errors. P4 is an oracle simulation reference. P2 and P3 must share the same mean target predictor so their comparison isolates uncertainty/risk treatment.

## Integration objective

The final end-to-end research story is:

PC-FMCW ISCAI sensing/communication → target tracking → target prediction → trajectory-conditioned connectivity forecast → predictive/risk-aware autonomous motion planning → closed-loop sensing/communication/mobility evaluation.

This preserves the upstream PC-FMCW work while adding a distinct robotics decision layer and removes dependence on CMHT/Rad-R for the core simulation study.
