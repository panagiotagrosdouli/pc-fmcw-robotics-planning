# PC-FMCW → Robotics Planning Bridge

## Purpose

This document defines the simulation-only bridge between the Phase-Coded FMCW (PC-FMCW) ISCAI study in `PanagiotaGr/ISCAI_pc_fmcw` and the Stage-9 autonomous-motion-planning stack in this repository.

The goal is to evaluate predictive connectivity-aware motion planning without requiring an external autonomous-driving dataset. The study is therefore a controlled, reproducible, physics/model-based closed-loop simulation study. It must not be described as real-world validation.

## Upstream PC-FMCW chain

The upstream project studies the following processing chain:

PC-FMCW generation → DPSK phase coding → optical transmission → coherent reception → group-delay filtering → range-Doppler processing → target detection → Multidimensional Hough Transform trajectory estimation → adaptive illumination.

The robotics extension starts after target-state / trajectory estimation. It does not replace the upstream sensing and communication study.

## Stage-9 interface

At planning time k, the bridge exposes:

- ego state x_e(k) = [x, y, yaw, v]
- estimated target state / recent target history
- a common predicted target trajectory used for dynamic safety
- candidate ego trajectories generated by the motion planner
- a PC-FMCW-informed analytical or explicitly declared surrogate link-quality model evaluated along each candidate trajectory

For candidate trajectory tau_i, future relative geometry is

r_i(k+j) = p_target_hat(k+j) - p_ego_i(k+j).

The connectivity predictor maps trajectory-conditioned relative geometry to modeled quantities such as SNR, BER, outage probability, goodput, or a normalized connectivity score. A metric should only be described as directly PC-FMCW-derived when its equations and parameters are explicitly traceable to the upstream PC-FMCW implementation. Otherwise the correct description is PC-FMCW-informed analytical connectivity model or connectivity surrogate/model.

## Planner variants and fairness

- **P0:** mobility-only baseline; no connectivity term. It still uses the common predicted target trajectory for dynamic safety.
- **P1:** reactive connectivity-aware baseline; connectivity scoring uses the present/myopic target state, while dynamic safety uses the common predicted target trajectory.
- **P2:** predictive connectivity-aware planner; connectivity scoring uses the common predicted future target trajectory.
- **P3:** risk-aware predictive planner; uses the same mean target predictor and link-predictor interface as P2 and propagates declared target-prediction uncertainty with Monte Carlo samples.
- **P4:** non-deployable oracle connectivity reference. Simulator future target truth may be used only for connectivity forecasting. Dynamic safety uses the same common predicted target trajectory as P0–P3.

All planners share the candidate generator, vehicle limits, road/static-obstacle filtering, and time-aligned dynamic-target safety logic. P4 must not receive an oracle collision-avoidance advantage.

## Closed-loop protocol

1. Generate a deterministic scenario from a documented seed and parameter set.
2. Simulate target ground-truth motion.
3. Produce the target information available to the planner from the declared observation/tracking model.
4. Compute the common mean target prediction without exposing future truth to P0–P3.
5. Generate dynamically consistent ego candidate trajectories.
6. Hard-filter candidates using vehicle/road/static-obstacle constraints and the common time-aligned predicted target trajectory.
7. Evaluate mobility and, where applicable, reactive/predictive/risk-aware connectivity costs.
8. For P4 only, allow simulator target truth in the connectivity-forecast input after the common safety filter has been defined.
9. Select a candidate and execute only its first control action.
10. Advance the simulation and repeat until termination.

This is receding-horizon closed-loop simulation. Future simulator truth is not a deployable planner input and is restricted to P4 connectivity forecasting.

## Scenario family

The dataset-free benchmark should cover parameterized scenario families rather than a single hand-picked trajectory:

- lead vehicle with changing speed
- cut-in / lane-change target
- crossing target
- geometry-driven link degradation
- target maneuver with prediction-model mismatch
- combined safety/connectivity conflict

Each scenario family should be swept over multiple seeds and physically meaningful initial conditions. Results should be aggregated across scenarios/seeds, not reported from one illustrative run.

## Evaluation

Primary mobility/safety metrics:

- travel time / progress
- path length
- minimum inter-vehicle distance
- collision-boundary realized TTC when defined
- collision / infeasibility rate

Primary modeled connectivity metrics:

- outage probability/fraction
- SNR
- BER
- goodput
- connectivity risk statistic for P3

Realized collision-boundary TTC is an evaluation diagnostic computed from realized simulator states under a constant-relative-velocity assumption. It is not exposed to any planner as future information.

Planning comparisons use matched scenario/seed realizations. The analysis reports paired effects with bootstrap uncertainty, paired Wilcoxon tests, and Holm multiplicity correction. Episode-level robustness figures may use deterministic 95% bootstrap confidence intervals over simulated episodes.

## Scientific claim boundary

The simulation does **not** constitute a new optical measurement campaign, a real-vehicle trial, or real-world autonomous-driving validation.

Use the phrase **PC-FMCW connectivity** only when the link metric is generated by a frozen model whose equations and parameters are explicitly traceable to the upstream PC-FMCW system. Otherwise use **PC-FMCW-informed analytical connectivity model** or **connectivity surrogate/model**.

Synthetic perturbations are declared observation/prediction/model perturbations in the simulation; they are not evidence of a calibrated physical sensor-noise distribution unless such calibration is separately established. P2 and P3 share the same mean target predictor so their comparison isolates uncertainty/risk treatment. P4 uses the same predicted target for dynamic safety and may use future truth only for connectivity forecasting.

Bootstrap intervals quantify variation across controlled simulated episodes and must not be described as physical measurement uncertainty.

## Integration objective

The final end-to-end research story is:

PC-FMCW ISCAI sensing/communication → target tracking → target prediction → trajectory-conditioned connectivity forecast → predictive/risk-aware autonomous motion planning → closed-loop sensing/communication/mobility evaluation.

This preserves the upstream PC-FMCW work while adding a distinct robotics decision layer and removes dependence on CMHT/Rad-R for the core simulation study. Detailed paper-method definitions and claim boundaries are maintained in `docs/PAPER_METHODS.md`.
